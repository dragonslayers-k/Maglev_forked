# 원본 Maglev 월간 업데이트 관리 정책

## 1. 저장소 관계

- 사용자 저장소: https://github.com/dragonslayers-k/Maglev_forked
- 원본 저장소(Upstream): https://github.com/Kaos599/Maglev
- GitHub 저장소 유형: Public Fork
- 현재 기준 브랜치: `main`
- 통합 브랜치: `dev`

이 저장소는 원본의 Fork이지만 별도의 저장소입니다. 이 저장소의 커밋·브랜치·릴리스가 원본 저장소에 자동 반영되지 않습니다. 원본에 변경을 가하거나 원본 관리자의 권한을 사용하는 구조가 아닙니다.

원본과의 Fork 관계는 월간 변경 비교를 쉽게 하기 위한 출처 연결입니다. 원본 업데이트를 자동으로 덮어쓰지 않습니다.

## 2. 월간 자동 감지

`.github/workflows/monthly-upstream-review.yml`이 매월 1일 한국시간 오전 9시에 실행되며, 수동 실행도 지원합니다.

- Fork `main`과 원본 `main`의 커밋 SHA를 비교합니다.
- 원본에 반영할 변경이 있거나 두 저장소가 분기된 경우, 월별 검토 Issue를 생성합니다.
- 동일 월에 열린 검토 Issue가 이미 있으면 중복 생성하지 않습니다.
- 자동 병합·자동 APK 배포는 수행하지 않습니다.
- 실행 결과와 비교 커밋 목록은 Actions Summary에 기록합니다.

## 3. 월간 점검 항목

매월 첫째 주에 다음 항목을 확인합니다.

1. 원본 Maglev의 `main` 커밋, 태그, Release, 변경 로그
2. 브라우저·미디어 감지·HLS·DASH·다운로드 엔진의 변경
3. Android/WebView, Expo, React Native, Rust 및 핵심 의존성 변경
4. 보안 권고, 취약점, 라이선스 및 배포 조건 변경
5. 원본 변경이 이 포크의 수정 파일과 충돌하는지 여부

점검 결과는 날짜, 원본 커밋 SHA, 변경 요약, 반영 여부, 보류 사유를 기록합니다.

## 4. 업데이트 반영 절차

원본 변경을 발견해도 `main` 또는 `dev`에 바로 동기화하지 않습니다.

1. 원본과 현재 `main`의 차이를 비교합니다.
2. 변경 파일과 이 포크의 수정 파일을 대조합니다.
3. 기능 개선·보안 수정·버그 수정 중 실제로 필요한 항목을 선별합니다.
4. `upstream-sync/YYYY-MM` 작업 브랜치에서 반영합니다.
5. 충돌이 있으면 기존 사용자 기능과 감지 로직을 보존하는 방향으로 수동 병합합니다.
6. 타입 검사, JS 테스트, Rust 테스트, Android Kotlin 테스트 및 빌드를 실행합니다.
7. 검증 결과와 변경 내역을 한국어 문서로 기록한 뒤 Draft PR로 `dev`에 제출합니다.
8. 회귀 검증을 통과한 변경만 `dev`에 통합하고, 릴리스 준비가 끝난 시점에 `main`으로 승격합니다.

## 5. 반영하지 않는 경우

다음 상황에서는 업데이트를 보류하고 사유를 기록합니다.

- 원본 변경이 이 프로젝트의 기능과 무관한 경우
- 기존 수정 기능을 제거하거나 동작을 바꾸는 경우
- 라이선스·보안·빌드 호환성을 확인할 수 없는 경우
- 충돌 해결 후 회귀 테스트가 통과하지 않는 경우
- 원본 변경이 불완전하거나 후속 수정이 예상되는 경우

## 6. 브랜치 역할

| 브랜치 | 역할 |
|---|---|
| `main` | 검증된 릴리스 기준선. 직접 개발 금지 |
| `dev` | 검증된 기능 통합 브랜치 |
| `feature/*` | 기능별 개발 및 테스트 |
| `upstream-sync/YYYY-MM` | 월간 원본 업데이트 검토 및 병합 전용 |

`upstream`은 Git remote의 별칭이지 별도 개발 브랜치가 아닙니다. 원본 저장소를 추적하기 위해 동일한 코드를 담은 불필요한 `upstream/*` 브랜치를 만들지 않습니다.

- 현재 확인 결과: Fork의 `main`은 원본 `main`과 동일한 커밋을 가리킵니다.
- 월간 자동 병합: 사용하지 않음
- 월간 변경 감지 및 수동 검토 후 PR 방식: 채택

## 8. 앱 내 업데이트 경로

설치된 사용자 APK는 이 포크의 GitHub Releases만 업데이트 대상으로 조회합니다. 원본 Maglev의 새 버전을 발견하면 즉시 설치하지 않고, 코드·보안·라이선스·호환성을 검토해 포크에 선별 반영한 뒤 이 포크의 새 Release를 게시합니다.

정식 업데이트는 `v주버전.부버전` 태그와 ABI별 APK, GitHub Release가 제공하는 SHA-256 digest가 모두 있어야 감지됩니다. 서명 인증서가 기존 설치 APK와 일치해야 Android가 정상적인 앱 업데이트로 설치할 수 있습니다. 첫 정식 Release 전에 릴리스 서명 키를 설정하고 동일한 키를 안전하게 보관해야 합니다.

## 9. 라이선스

원본 Maglev의 GPL-3.0 라이선스와 저작권 고지를 유지합니다. 원본 변경분을 반영할 때도 출처와 변경 이력을 보존합니다. 별도 라이브러리나 코드가 추가되면 라이선스 호환성과 고지 의무를 먼저 확인합니다.
